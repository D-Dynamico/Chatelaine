## Surprises

- **The rules file was the wrong one (#5).** CLAUDE.md, which every session loads first,
  said the delay is "clamped" and that "every API" accepts it. Taken literally, a clamp
  turns `delay=10001` into 10000 and returns 200, and the `/health` route would honour a
  delay. That code would have looked compliant against the file most likely to be read,
  while failing §9, the simulation tests and a Stage 1 exit criterion. A one-word
  ambiguity in the always-loaded summary outranks a correct detail doc in practice, so the
  summary now uses the same words as §9.
- **A correct-looking interceptor chain could never report a timeout (#16).** With the
  timeout interceptor outside the request log, a timeout unsubscribes from the log's stream
  rather than erroring through it. The log's `finalize` then sees neither a response nor an
  error and records `cancelled`. Every unit test of the log in isolation would pass; only
  the order was wrong. The new `requestLogInterceptor` test runs through the full
  registered chain so it goes red if the order regresses, and `errorInterceptor` gets a
  test proving it passes an existing `CLIENT_TIMEOUT` `ApiError` through unchanged.
