## Surprises

- **A contract test that could not fail (2.7).** The DynamoDB list applied the scope twice,
  in the key query and again in memory, so the key condition that D7 is about was
  untestable. Found by asking why 31 tests passed on the first run. Fixed by applying the
  scope in one place per adapter; the mutation check now bites.
- **A green run that asserted nothing about status codes (2.3).** An intermediate edit of a
  test helper dropped every status assertion and all 166 tests still passed. The body
  assertions carried them, which is exactly how a status regression would slip through.
- **A guard check that refused to run (2.6).** A shell quoting error meant my mutation did
  not apply. Because every mutation script asserts that it changed the file, it failed
  with "no change" instead of passing and making the guard look proven.
- **Library behaviour, each confirmed before relying on it:** fast-xml-parser's `isArray`
  path type depends on `jPath`; MongoDB's `Filter` type keeps the domain's `readonly`
  fields; the Mongo driver refuses an empty `insertMany` and stores `undefined` in `$set`
  as null; zod reports an unknown key and a failed refinement together.

**If the day slips:** 2.7 moves to the end of Stage 7 (§31). Steps 2.1 to 2.6 still prove
the contract on two adapters.
