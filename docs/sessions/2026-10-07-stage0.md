## Scope

Wrote the planning set before any code: `CLAUDE.md`, every file in `docs/`, the README

what was decided there so the first Claude Code session starts with it.

## Decisions made in planning

- **Free hosting only, no card** (DJK's constraint). MongoDB Atlas M0, Render free web
  service, Vercel. AWS was ruled out because new accounts since July 2025 need a card and
  no longer get free API Gateway calls (D8).
- **All three storage options**, behind one repository contract. The file adapter writes
  XML because the brief names XML (D6). DynamoDB uses a single-table design and runs on
  DynamoDB Local in Docker and CI (D7).
- **Role at login is a claim the server checks.** Mismatch is the same 401 as a wrong
  password (D11).
- **Records are IT service requests** with an access level, so the table can show what a
  General User can and cannot see (D28).
- **The delay requirement becomes a latency lab** with three loading strategies and a
  request timeline (D16, D23). A `fail` parameter makes error states reachable (D17).
- **Render's cold start is shown, not hidden,** through the boot splash and initializer
  (§16, D21).
- **Week plan:** one stage per day, Stage 0 to Stage 7 (§31). If a day slips, the DynamoDB
  adapter moves to the end first.

## Surprises

- **`LAST_ADMIN` cannot trigger through a single request.** The caller is always an active
  admin and cannot change their own account (`SELF_ACTION`), so at least one admin always
  remains. The check stays as defence in depth for concurrent cross-demotion and is
  unit-tested at the service level instead of through the API (D30). The API doc, test
  plan, frontend doc and Stage 5 exit criteria were corrected to match.
- **Native `bcrypt` needs a compiler on Windows,** so the docs specify `bcryptjs` (D12).
  `CLAUDE.md` says "bcrypt", meaning the algorithm.
