## Surprises

- **The lockfile guard let a stripped `web/` lockfile through (3.1).** A second
  `npm install` removed 270 lines (15 rolldown bindings), yet `check-lockfile.js` passed.
  `web/` has two rolldowns: 1.2.8 hoisted, and 1.2.13 nested under `vite`. npm stripped
  the nested copy's bindings; the guard, mirroring Node's lookup, walked up and found the
  hoisted 1.2.8 bindings of the same names and counted them. On Linux, `npm ci` would
  have given vite's rolldown no matching native binding. The guard now also checks that
  the resolved copy's version satisfies the spec (exact, `~` and `^`, the only forms in
  either lockfile). Verified: it fails the stripped lockfile (15 missing, exit 1) and
  passes both real ones; the restored lockfile was compared byte for byte with the
  original. `api/` gets the same script, so the two copies stay identical.
- **§22 claimed AA for every pair, and two did not meet it (3.2).** Light brass on its
  tint was 4.36:1, so the Admin badge, the most visible access signal, would have failed
  AA in light mode. And `--line` was documented for input borders at about 1.5:1, below
  the 3:1 a control boundary needs. Both claims were written before anything was
  measured; this is the reason the plan asked for measured ratios. Fixed by darkening
  brass slightly (`#855B15`) and by giving input borders `--ink-muted` through Material's
  `outline` role, keeping `--line` for dividers.
