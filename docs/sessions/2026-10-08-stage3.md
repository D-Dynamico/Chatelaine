- [x] 3.4 **Translate HTTP at the edge.** Environments with `apiBaseUrl`, the
      `SILENT_AUTH` context token, `apiUrlInterceptor`, `authInterceptor`,
      `errorInterceptor` (401 handling and `CLIENT_TIMEOUT` pass-through) and
      `timeoutInterceptor` with fake timers.
      *Done together as one commit, without `timeoutInterceptor`.* The two depend on each
      other: `restore()` drops a dead token on a 401 `ApiError`, which only exists once
      `errorInterceptor` has mapped it, and that interceptor clears the session. The
      timeout reads its limit from `LatencySettingsStore`, so it moved to 3.5 with the
      other two interceptors the lab drives. Decisions: `SessionStore` reads the token
      from storage at construction, and `isSignedIn` needs both a token and a user, so a
      token waiting for `/me` is not a session. `restore()` never errors (the initializer
      must not reject); it clears the token on a 401 and keeps it on any other failure,
      since the server may only be waking. Services request `api/...` paths
      (`API_PATHS`) and `apiUrlInterceptor` resolves them against an `API_BASE_URL`
      injection token (environment by default, overridable in tests), so later
      interceptors see absolute URLs. `apiPathOf()` classifies a URL relative to the base
      and returns null for other origins: `authInterceptor` therefore never sends the token
      off-site, which §17 did not say and now does. `ApiError` extends `Error`; the mapper
      only trusts a body whose code is one of the §13 codes, otherwise it is
      `UNEXPECTED_RESPONSE`, and status 0 is `NETWORK_ERROR` (client codes, each with a
      §25-voice message). The expired-session redirect also carries `returnUrl` (§17
      updated). `withFetch()` is deprecated in Angular 22, where fetch is the default
      backend, so it is not used. `app/testing/` holds fixtures and `provideTestHttp()`,
      which installs the real chain, and is excluded from the app build (§14 updated).
      Production `apiBaseUrl` is a placeholder until Stage 7 (open item). Verified: 34
      tests; mutation checks, each killed by the named test: dropping the `SILENT_AUTH`
      term, dropping the login exclusion, dropping the public-path exclusion, dropping the
      other-origin check, and clearing the token on any restore failure. See Surprises for
      the check script that could not report a failure.

## Surprises

- **The lockfile guard let a stripped `web/` lockfile through (3.1).** A second
  `npm install` removed 270 lines (15 rolldown bindings), yet `check-lockfile.js` passed.
  `web/` has two rolldowns: 1.2.8 hoisted, and 1.2.13 nested under `vite`. npm stripped
  the nested copy's bindings; the guard, mirroring Node's lookup, walked up and found the
  hoisted 1.2.8 bindings of the same names and counted them. On Linux, `npm ci` would
  have given vite's rolldown no matching native binding. The guard now also checks that
  the resolved copy's version satisfies the spec (exact, `~` and `^`, the only forms in
  either lockfile). Verified: it fails the stripped lockfile (15 missing, exit 1) and
  passes both real ones; the restored lockfile was compared byte for byte with the
  original. `api/` gets the same script, so the two copies stay identical.
- **§22 claimed AA for every pair, and two did not meet it (3.2).** Light brass on its
  tint was 4.36:1, so the Admin badge, the most visible access signal, would have failed
  AA in light mode. And `--line` was documented for input borders at about 1.5:1, below
  the 3:1 a control boundary needs. Both claims were written before anything was
  measured; this is the reason the plan asked for measured ratios. Fixed by darkening
  brass slightly (`#855B15`) and by giving input borders `--ink-muted` through Material's
  `outline` role, keeping `--line` for dividers.
- **My mutation script reported "survived" for mutants that never ran (3.4).** The first
  five checks all said the guard survived removal. None had run: `noUnusedLocals` and
  `noUnusedParameters` rejected each mutant at compile time (removing a condition left an
  import or a parameter unused), and the script read "no failed tests" as survival.
  Wrong in the safe direction this time, but the same script reading a passing build as a
  kill would have been the dangerous version. It now prints INCONCLUSIVE unless a test
  summary line appears, and mutants are written to keep compiling (a condition made
  vacuous instead of deleted). All five were then killed.
